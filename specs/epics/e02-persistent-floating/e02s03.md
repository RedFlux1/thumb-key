# e02s03 — Visual indicator + settings UI polish

**type:** feat
**risk:** P2
**context:** domain
**bcps:** 3

## §1 Business Narrative

With persistent floating mode wired and key events working without InputConnection, the user needs clear visual feedback that persistent mode is active. Without an indicator, it's confusing when the keyboard doesn't auto-hide — the user may think it's a bug.

This story adds a lock icon next to the drag handle on the floating keyboard (only visible when persistent is enabled) and polishes the settings UI — placing the "Keep keyboard visible" checkbox in the floating mode settings section, properly gated behind the floating mode toggle.

## §5 Main Flow

1. User enables floating mode in settings
2. "Keep keyboard visible" checkbox becomes enabled
3. User toggles "Keep keyboard visible" ON
4. The floating keyboard now shows a small lock icon (🔒) next to the drag handle
5. User flings down → floating keyboard dismissed, lock icon gone (persistent disabled)
6. User re-enables persistent → lock icon reappears

## §6 Alternative Flows

- **Floating mode OFF:** "Keep keyboard visible" checkbox is greyed out / disabled. Tapping shows a tooltip: "Enable floating mode first."
- **Persistent OFF:** Lock icon is not shown on the floating keyboard. Drag handle appears as normal.
- **Docked keyboard:** No visual changes — the lock icon only applies to the floating overlay.
- **Theme changes:** Lock icon uses MaterialTheme.colorScheme.onSurfaceVariant, matching the drag handle icon color. Automatically adapts to light/dark theme.

## §17 Gherkin Acceptance Criteria

```gherkin
Scenario: Settings checkbox gated behind floating mode
  Given the user is in Floating Mode settings
  When floating mode is OFF
  Then the "Keep keyboard visible" checkbox is disabled

Scenario: Settings checkbox enabled when floating is on
  Given the user is in Floating Mode settings
  When floating mode is ON
  Then the "Keep keyboard visible" checkbox is enabled

Scenario: Lock icon visible when persistent is active
  Given floating mode is ON
  And persistent mode is ON
  And the floating keyboard is visible
  Then a lock icon is displayed next to the drag handle

Scenario: Lock icon hidden when persistent is off
  Given floating mode is ON
  And persistent mode is OFF
  And the floating keyboard is visible
  Then no lock icon is displayed

Scenario: Setting persists across restart
  Given persistent mode is ON
  When the user force-kills and reopens Thumb-Key
  Then the persistentFloatingEnabled setting is still 1
  And the lock icon appears on the next floating keyboard session
```

## §18 Out of Scope

- Customizable indicator (position, icon choice, color)
- Persistent mode indicator on docked keyboard (N/A — persistent is floating-only)
- Toast or notification when persistent mode activates (too noisy)

## Steps

1. Add "Keep keyboard visible" checkbox to OtherSettingsScreen.kt, gated behind floating mode toggle → verify: `./gradlew assembleDebug`
2. Wire checkbox to persistentFloatingEnabled field via OtherSettingsUpdate → verify: `./gradlew assembleDebug`
3. Add lock icon (Icons.Outlined.Lock) in ComposeKeyboardView next to drag handle, conditionally visible when isPersistentFloatingEnabled() is true → verify: `./gradlew assembleDebug`
4. Ensure icon updates reactively via observeAsState on settings LiveData (same pattern as isFloating) → verify: `./gradlew assembleDebug`
5. Full preflight + manual visual verification → verify: `./gradlew lintKotlin lint assembleDebug`

## Risks

- **Icon crowding:** Adding an icon next to the drag handle may look cramped on narrow floating keyboards. Mitigation: the lock icon is small (12.dp, same size as the drag handle icon) and placed with a small spacer — minimal visual impact.
- **Reactivity lag:** observeAsState should update immediately, but Room DB writes have a small delay. Mitigation: the current isFloating pattern already works well — follow the same approach.
