# e06s04 — Dynamic scaling, compact search, 4x1 search pad

## Dynamic scaling (floating + docked)

- `EmojiPicker` wraps content in `BoxWithConstraints`: grid width is
  `maxWidth - 56.dp pad`; columns = `(gridWidth / 48.dp).coerceIn(3, 8)`;
  emoji font = `cell * 0.52`. Narrow floating widths drop to 3-4 columns
  with readable glyphs; full-width docked goes up to 8. No fixed `sp`.
- The 4 pad keys size themselves from the standard `keyHeight`/`keyWidth`
  settings via `KeyboardKey`, so floating and docked both fill naturally.

## Compact search field

- `OutlinedTextField` is `readOnly` (tapping must not summon a system
  keyboard from inside the IME), 13sp hint / 14sp text, tight padding,
  trailing clear-X only when the query is non-empty.

## 4x1 vertical search pad (keyboards/EmojiSearchPadKeys.kt)

- Exactly the extra letter column from `NUMERIC_KEYBOARD_NO_EXPANDED`
  (NOThumbKeyDataDrivenExpanded numeric layer): a/g/m/s centers with the
  same 8-way swipe letters including æøå, same LARGE/MUTED styling.
- Built like the rest of the keyboard: real `KeyItemC`s rendered by the
  real `KeyboardKey` composable inside the picker (as a `searchPad` slot),
  with a new `KeyAction.EmojiSearchInput(text)` routed through
  `performKeyAction` via an `onEmojiSearchInput` callback (same pattern as
  the `onToggle*` family), threaded through `KeyboardKey`. Typing appends
  to the hoisted `emojiQuery` state; clearing uses the field's clear-X.
- 56dp strip docked right of the grid, inside the picker, in both EMOJI
  branches. No custom gesture code.
