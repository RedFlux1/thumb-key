# e06s01 — Bundled emoji data + Kotlin search engine

Port Gboard's `EmojiSearchJniImpl` query path to pure Kotlin (no JNI).

## Data (`ui/components/keyboard/emoji/EmojiData.kt`)

- `enum class EmojiCategory` with res-independent labels: RECENTS, SMILEYS,
  GESTURES, HEARTS, NATURE, FOOD, OBJECTS, SYMBOLS.
- `data class EmojiEntry(val emoji: String, val keywords: List<String>, val category: EmojiCategory)`.
- `val BUNDLED_EMOJI: List<EmojiEntry>` (~150 entries, system-font glyphs only).
  Each entry carries 2-5 lowercase English keywords (e.g. joy -> "joy happy laugh tears").
- No proprietary data: keywords are hand-written, glyphs are Unicode standard.

## Engine (`ui/components/keyboard/emoji/EmojiSearchEngine.kt`)

Mirrors `jab` filter + `Pair` cache without proto/JNI:

- `normalize(query)`: `lowercase(US).trim().replace(/\s+/, " ")`, empty on blank.
- `search(query, limit=200)`: split normalized query on spaces; entry matches if
  every token is a substring of the emoji string or any keyword. Rank: emoji
  exact > keyword prefix > keyword substring, then category order.
- 1-entry cache: `Pair(normalizedQuery, List<EmojiEntry>)` reused on repeat
  query (mirrors Gboard `Pair<yrc,yrd>`).
- `emojisByCategory(category)` for tab browsing.
- `object` singleton, thread-safe via `@Volatile` cache ref, no coroutines.
