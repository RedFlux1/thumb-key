# e05s02 — Dock target + dock hint (resize DROPPED per user feedback)

**type:** feat
**risk:** P1
**context:** domain
**bcps:** 2
**status:** implemented-without-resize

## §1 Narrative

Gboard floating keyboard has 8 edge/corner resize handles plus a
drag-to-dock target. User feedback: resizing is unnecessary for Thumb-Key.
This story ships only the dock side: bottom dock target while dragging
("Drag here to exit floating mode", Gboard `floating_keyboard_dock_hint`
parity) plus first-run hint text. Resize handles, scale persistence, and
the size slider were removed again (commit "drop floating resize").

Kept: max-width cap, opacity, per-orientation position memory.

## §17 Acceptance

```gherkin
Scenario: Dock target drop exits floating
  Given floating is on and the user drags the handle downward
  Then a dock bar appears below the keyboard, highlighted once the drag
  passes the arm distance
  When released over the dock bar (or fling-down)
  Then floating exits (persistent-aware, same as fling-down)

Scenario: No resize UI
  Given floating is on
  Then no resize handles are shown and keyboard scale is fixed at 1.0
```
