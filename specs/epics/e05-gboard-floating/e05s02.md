# e05s02 — Resize + scale + dock hint (Gboard parity)
# Replaces width-fraction-only cap with Gboard WidgetSoftKeyboardView/ScaledKeyboardViewInner semantics.

**type:** feat
**risk:** P0
**context:** domain
**bcps:** 5

## §1 Narrative

Gboard floating keyboard scales (`WidgetSoftKeyboardView.s/g`, alpha fade `j`)
and re-lays-out via `ScaledKeyboardViewInner.d/b/c` with 8 resize handles
(top/bottom/left/right + 4 corners) plus a drag-to-dock target
(`floating_keyboard_dock_hint`, "Drag here to exit floating mode").
Thumb-Key only caps width. This story adds scale + handles + dock target and
removes the old cap-only path.

## §5 Main flow

1. Floating keyboard shows 8 resize handles (4 corners scale both axes,
   4 edges scale one axis), each min 24dp touch target, with content
   descriptions `Resize keyboard on the <edge|corner>`.
2. Dragging a handle updates `scaleFactor` live (0.5–2.0, Gboard float-range
   parity), fades content alpha during gesture, persists on release
   (per-orientation, same store as position).
3. Content rescales around the keyboard (graphicsLayer scale, Gboard `nhg`
   parity); max size still clamps to screen minus margins (`r()` parity).
4. While dragging the move handle, a bottom dock target appears
   ("Drag here to exit floating mode"); dropping there exits floating
   (same as fling-down, persistent-aware).
5. Unsupported case: expand-in-floating emoji/clipboard docked view disables
   resize handles (Gboard "Current keyboard does not support resizing" parity:
   handles hidden, no crash).

## §17 Acceptance

```gherkin
Scenario: Corner resize scales both axes
  Given floating is on at scale 1.0
  When the user drags the bottom-right corner outward
  Then the keyboard grows proportionally up to scale 2.0 and persists

Scenario: Edge resize scales one axis
  Given floating is on
  When the user drags the right edge
  Then width changes, height is unchanged

Scenario: Dock target exits floating
  Given floating is on and the user drags the handle to the bottom dock bar
  When released over the dock target
  Then floating exits (persistent-aware, same as fling-down)

Scenario: Resize hidden when docked for emoji/clipboard
  Given expand-in-floating is off and emoji panel forced docked
  Then resize handles are hidden in that state
```
