# e05s01 — Floating controller foundation: move physics + lifecycle
# Replaces IMEService ad-hoc overlay code with Gboard-style controller.

**type:** feat
**risk:** P0
**context:** infra
**bcps:** 5

## §1 Narrative

Extract all floating-window logic from `IMEService` into a new
`FloatingKeyboardController` (same pattern as Gboard's
`AccessoryInputModeManager.switchToFloatingKeyboardMode` /
`WidgetViewDragToMoveHandler`). The controller owns position, velocity-tracked
drag, screen-margin clamping, per-orientation memory, and dismiss. `IMEService`
keeps thin delegates. Behavior for persistent mode is preserved, not changed.

## §5 Main flow

1. User enables floating → controller `enterFloating()` builds overlay params
   (`WRAP_CONTENT`, `TYPE_APPLICATION_OVERLAY`, `NOT_TOUCH_MODAL |
   LAYOUT_IN_SCREEN | NOT_FOCUSABLE`), gravity `TOP|START`, x/y from
   per-orientation store, alpha from opacity.
2. Drag handle move → controller `onDrag(dx,dy)` accumulates raw delta, clamps
   to screen minus window size minus status-bar top inset (Gboard `r()` minus
   margins), updates layout live (Gboard `njt.a`).
3. Release → velocity from `VelocityTracker` (1000 px/s unit, Gboard parity);
   fling-down past threshold dismisses (existing `onFlingDismiss` semantics);
   otherwise `onDragEnd()` persists position for current orientation.
4. Rotation → controller recomputes max size (`r()` parity) and re-clamps;
   existing orientation tracking kept.
5. Lifecycle (`onWindowHidden`, `onFinishInput`, `onEvaluateInputViewShown`)
   delegates to controller's `shouldKeepVisible()` (persistent-aware).

## §17 Acceptance

```gherkin
Scenario: Drag moves and persists per orientation
  Given floating is on
  When the user drags the handle and releases
  Then the window follows the drag, stays fully on-screen below the status bar
  And the position is restored after rotation back and forth

Scenario: Fling-down dismiss unchanged
  Given floating is on
  When the user flings down on the drag handle
  Then persistent-on hides IME + clears persistent; persistent-off returns to docked

Scenario: No behavior change when docked
  Given floating is off
  Then no overlay exists and docked input is untouched
```

## Steps

1. Add `FloatingKeyboardController.kt` (IME-scoped, no AndroidView code in
   IMEService) → `./gradlew assembleDebug`
2. Move show/hide/drag/dragEnd/fling/clamp/statusBar/orientation there;
   `IMEService` delegates → `./gradlew assembleDebug`
3. Velocity-tracked drag: threshold 2500px/s down-fling (keep current value,
   document as Gboard `computeCurrentVelocity(1000)` parity) → `assembleDebug`
4. Full preflight → `lintKotlin lint assembleDebug`
