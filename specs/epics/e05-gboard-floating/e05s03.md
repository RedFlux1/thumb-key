# e05s03 — Auto-float landscape + settings replace + persistent rewire
# Completes Gboard parity, removes old settings path.

**type:** feat
**risk:** P1
**context:** domain
**bcps:** 4

## §1 Narrative

Gboard has "Enable auto float keyboard in landscape" plus opacity/scale/width
controls and a dock-hint tooltip counter. Thumb-Key settings show
opacity + expand-in-floating + max-width only. This story replaces that block
with the Gboard set (auto-float landscape, scale slider, width cap, opacity,
dock-hint reset) and rewires persistent mode onto the new controller, deleting
the old `onDrag`/`maxWidthFraction`-only code path.

## §5 Main flow

1. Settings → Floating section shows: floating toggle, persistent toggle
   (unchanged), auto-float-in-landscape toggle, scale slider (50–200%),
   width-cap slider (existing), opacity slider (existing), "Reset dock hint".
2. Auto-float on + rotate to landscape → enters floating automatically;
   rotate back → restores previous docked/floating state (does not override
   an explicit user toggle mid-session).
3. Persistent semantics unchanged (keep visible without focus, lock icon,
   hide on fling/dock, no-IC key events from e02s02).
4. Old code deleted: `IMEService.onDrag` inline clamp, old
   `SubcomposeLayout` width-only cap, old settings rows. No dead code.

## §17 Acceptance

```gherkin
Scenario: Auto-float in landscape
  Given auto-float is on and the keyboard is docked in portrait
  When the device rotates to landscape
  Then floating activates; rotating back restores docked

Scenario: Explicit toggle wins mid-session
  Given auto-float is on and the user manually docks in landscape
  Then rotation does not force floating back until next session trigger

Scenario: Persistent still works
  Given persistent is on
  Then focus loss keeps the overlay (new controller path) with lock icon

Scenario: Settings persist
  Given the user sets scale 1.2 + auto-float on
  When the app restarts
  Then both values are restored
```
