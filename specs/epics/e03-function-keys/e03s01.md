integration in KeyboardScreen, digit-to-F-key mapping in performKeyAction, and
modifier status indicator display.

### 2. Wire onToggleFnMode callback in KeyboardScreen

- In KeyboardScreen.kt, add `onToggleFnMode: (enable: Boolean) -> Unit` parameter
  (after onToggleMetaMode in the function signatures for both drawKeyboard and
  emoji/clipboard branches)
- Add the toggle handler lambda:

```kotlin
onToggleFnMode = { enable ->
    if (enable) {
        if (activeModifiers and FN_MODE_ON == 0) {
            activeModifiers = activeModifiers or FN_MODE_ON
        } else if (modLocked and FN_MODE_ON == 0) {
            modLocked = modLocked or FN_MODE_ON
        } else {
            activeModifiers = activeModifiers and FN_MODE_ON.inv()
            modLocked = modLocked and FN_MODE_ON.inv()
        }
    } else {
        activeModifiers = activeModifiers and FN_MODE_ON.inv()
        modLocked = modLocked and FN_MODE_ON.inv()
    }
},
```

- Add "Fn " to the modifier status indicator buildString when FN_MODE_ON is active
- Pass onToggleFnMode through KeyboardKey composable calls

### 4. Map digits to F-keys when Fn is active

- In performKeyAction(), in the CommitText branch, before the existing
  modifier-chord logic, add Fn-mode digit mapping:

```kotlin
// Fn mode: map digits and -/= to function keys
if ((activeModifiers and FN_MODE_ON) != 0 &&
    action.text.length == 1
) {
    val fnKeyCode = when (action.text[0]) {
        '1' -> KeyEvent.KEYCODE_F1
        '2' -> KeyEvent.KEYCODE_F2
        '3' -> KeyEvent.KEYCODE_F3
        '4' -> KeyEvent.KEYCODE_F4
        '5' -> KeyEvent.KEYCODE_F5
        '6' -> KeyEvent.KEYCODE_F6
        '7' -> KeyEvent.KEYCODE_F7
        '8' -> KeyEvent.KEYCODE_F8
        '9' -> KeyEvent.KEYCODE_F9
        '0' -> KeyEvent.KEYCODE_F10
        '-' -> KeyEvent.KEYCODE_F11
        '=' -> KeyEvent.KEYCODE_F12
        else -> KeyEvent.KEYCODE_UNKNOWN
    }
    if (fnKeyCode != KeyEvent.KEYCODE_UNKNOWN) {
        Log.d(TAG, "Fn key: char=${action.text[0]} → keyCode=$fnKeyCode")
        val ic = ime.currentInputConnection
        if (ic != null) {
            ic.sendKeyEvent(
                KeyEvent(KeyEvent.ACTION_DOWN, fnKeyCode)
            )
            ic.sendKeyEvent(
                KeyEvent(KeyEvent.ACTION_UP, fnKeyCode)
            )
        } else {
            ime.sendDownUpKeyEvents(fnKeyCode)
        }
        ime.ignoreNextCursorMove()
        onKeyEvent()
        return  // Bypass normal text commit / modifier chord logic
    }
}
```

- This mapping runs BEFORE the modifier-chord check, so Fn+digit takes priority
  over Ctrl/Alt/Meta+digit chords

### 5. Handle Fn clearing on key event (one-shot behavior)

- In the `onKeyEvent` callback in KeyboardScreen, ensure FN_MODE_ON is cleared
  from activeModifiers (alongside other one-shot modifiers) after a key event:

```kotlin
onKeyEvent = {
    val locked = modLocked
    activeModifiers = (activeModifiers and KeyEvent.META_SHIFT_ON) or locked
}
```

- FN_MODE_ON is not in META_SHIFT_ON, so it will be cleared. Locked Fn
  (in modLocked) persists. This is already the correct behavior since
  `modLocked or (activeModifiers and KeyEvent.META_SHIFT_ON)` preserves
  locked modifiers and clears all one-shot ones including Fn.
