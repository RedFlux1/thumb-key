# e04s02 — System capture parity (timestamp, html, sensitive, images)

Extend `ThumbKeyClipboardManager` to Gboard `fmg.b()` parity:

- Timestamp: use `ClipDescription.getTimestamp()` when >0 else `System.currentTimeMillis()` (Gboard `b()` lines: epochMilli/timestamp)
- HTML: read `ClipData.Item.getHtmlText()`; detect `Spanned` for rich-text metric equivalent (log only, no metrics pipeline)
- Sensitive: `Build.VERSION.SDK_INT>=33 && description.extras?.getBoolean("android.content.extra.IS_SENSITIVE")`; also treat password autofill hints as sensitive heuristic (no blocking, just flag)
- Text truncation: cap at 5000 chars (Gboard `fnm.b` equivalent; prevents DB bloat)
- MIME gate (keep existing `text/` gate for history insert, but):
  - If `text` non-empty -> `addItem(text, htmlText, itemType=rich?2:0, sensitive)`
  - Else if `uri` is `content://` and `mimeType.startsWith("image")` -> copy to internal `files/clipboard_images/<timestamp>.<ext>` via ContentResolver openInputStream (mirrors `fmn.b`), then `addItem(text="", htmlText=null, itemType=1, uri=internalUriString, sensitive)`
  - Wrap `coerceToText()` + `openInputStream()` in try/catch (existing crash guard extends to images)
- Keep `wasLastCopyOperationDoneViaSystem` semantics; image copies set true (must paste via system path until commitContent lands in s03)
- Keep `OnPrimaryClipChangedListener` registration lifecycle unchanged

Files:
- New `ClipboardImageFiles.kt`: `saveImageToInternal(context, sourceUri, timestamp): String?`, `deleteImageFile(path)`, `resolveImageDir()`
- `ThumbKeyClipboardManager` gains `addImageClip(uriString, mimeType, timestamp, sensitive)`
